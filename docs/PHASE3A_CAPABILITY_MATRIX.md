# Phase 3A — API capability matrix

Verified against official public documentation on **25 October 2026 (Asia/Kuala_Lumpur)**. Baseline `dfba94e`. Nothing below is an implemented integration or a live grant test. Source IDs link to the dated [research register](PHASE3A_API_RESEARCH.md#2-official-source-register).

## Classification rules

- **VERIFIED**: the public official contract/limit was read. Actual app authorization and runtime behavior remain separate open gates.
- **REQUIRES APPROVAL**: the contract exists, but the requested use needs missing purpose/access approval or review. A permission name is not an approval.
- **UNVERIFIED**: the specific field, guarantee, telemetry or app-specific contract was not established. Absence from one guide is not proof of global API absence.
- **NOT SUPPORTED**: the particular requested scenario contradicts an explicit documented restriction. This does not mean the API lacks a related, narrower capability.

Choose the most restrictive relevant row for a product action. An individual field being VERIFIED never overrides a REQUIRES APPROVAL/NOT SUPPORTED purpose or target restriction.

Graph read examples use `https://graph.threads.com/v1.0`; OAuth exchange/refresh examples use the unversioned auth paths shown below. T01 also recognizes graph.threads.net. Freeze one documented host/version per adapter and reverify before implementation; do not derive a Threads version from Facebook Graph versions.

Public search, posting, moderation, deleting Threads posts, insights/demographics, mentions, ghost posts and general webhooks are not recommended Phase 3B features.
